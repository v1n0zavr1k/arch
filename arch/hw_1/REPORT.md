# Отчёт: Scalar и SIMD вычисления

## Реализация

Все ядра доступны в Scalar и SIMD-вариантах. Арифметические операции принимают callable-объект; `binary_transform` выбирает ядро по `ExecutionPolicy`, поэтому сами операции не дублируют общий обход массива. xsimd обрабатывает полные векторные блоки, а остаток любой длины — скалярный хвост.

Реализованы сложение, вычитание, умножение и деление; сумма и среднее; SiLU и tanh-аппроксимация GELU; умножение row-major матриц. Для крупных массивов и матриц используется OpenMP при наличии поддержки. Деление целых на ноль и среднее пустого массива сигнализируют об ошибке; SIMD-функции проверяют указатели для непустых входов.

## Корректность

Тесты сравнивают Scalar и SIMD арифметику на размере, не кратном ширине SIMD, редукцию и значения активаций, а также результат SIMD умножения матриц с ожидаемыми значениями. Также сохранены тесты исходного Scalar-ядра.

## Производительность

`simd_bench` измеряет сложение массивов типов int32, float32 и float64 размеров 256, 4 096, 65 536 и 1 048 576 элементов. Для каждого варианта проводится прогрев и 7 измерений по 100 повторов; в CSV печатается медианное время в миллисекундах и speedup (Scalar/SIMD).

Замеры ниже получены на arm64 macOS, AppleClang 16, Release, с xsimd 14.3.0; OpenMP отключён, чтобы сравнить сами ядра без стоимости создания потоков. Это один запуск, малые размеры чувствительны к шуму измерений.

| Тип | Элементов | Scalar, мс | SIMD, мс | Ускорение |
|---|---:|---:|---:|---:|
| int32 | 256 | 0.0001 | 0.0001 | 0.88× |
| float32 | 256 | 0.0001 | 0.0001 | 0.88× |
| float64 | 256 | 0.0001 | 0.0001 | 0.97× |
| int32 | 4 096 | 0.0008 | 0.0008 | 1.06× |
| float32 | 4 096 | 0.0008 | 0.0006 | 1.27× |
| float64 | 4 096 | 0.0028 | 0.0028 | 0.98× |
| int32 | 65 536 | 0.0062 | 0.0062 | 0.99× |
| float32 | 65 536 | 0.0097 | 0.0095 | 1.03× |
| float64 | 65 536 | 0.0155 | 0.0159 | 0.98× |
| int32 | 1 048 576 | 0.1142 | 0.1128 | 1.01× |
| float32 | 1 048 576 | 0.1124 | 0.1173 | 0.96× |
| float64 | 1 048 576 | 0.2505 | 0.2559 | 0.98× |

На этом запуске SIMD арифметика примерно сравнима с Scalar: компилятор уже векторизует простой scalar-цикл, поэтому заметного ускорения нет. При OpenMP-замере накладные расходы потоков для этих размеров ухудшили результат; порог включения параллелизма следует подбирать под целевую машину. Бенчмарк не измеряет активации и матричное умножение.

## Сборка и запуск

```bash
brew install cmake ninja xsimd googletest libomp
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DOpenMP_ROOT="$(brew --prefix libomp)"
cmake --build build
ctest --test-dir build --output-on-failure
./build/simd_bench
```
